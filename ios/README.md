# Marketing Studio — iOS

Native SwiftUI prototype of the Marketing Studio spec (`../SPEC.md`). Frontend-only: all data is
mocked and persisted locally; all "AI" calls are simulated with delays. Architected so real APIs
can replace `MockAPI` without touching views.

## Build

Project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`
(never edit the `.xcodeproj` by hand — re-run generate after adding files):

```sh
cd ios
/opt/homebrew/bin/xcodegen generate
```

The Desktop folder is iCloud-synced, which taints bundles with xattrs and breaks codesign.
**Always build with DerivedData outside the Desktop** (a "Strip xattrs" run-script phase is also
in the target as belt-and-braces):

```sh
xcodebuild -project MarketingStudio.xcodeproj -scheme MarketingStudio -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone Air' \
  -derivedDataPath /private/tmp/claude-501/-Users-annybabeni-Desktop-goodies/5b6e75ad-07dd-45b3-9fc9-416837beda3e/scratchpad/DerivedData-ios \
  build 2>&1 | tail -30
```

Run on the booted simulator:

```sh
xcrun simctl install booted <DerivedData>/Build/Products/Debug-iphonesimulator/MarketingStudio.app
xcrun simctl launch booted com.northstar.marketingstudio
xcrun simctl io booted screenshot /path/to/shot.png
```

Target: iOS 17.0+, Swift 5.9, SwiftUI lifecycle, dark appearance forced, portrait iPhone (iPad allowed).

## Navigation

- Five tabs: Home, Studio, Projects, Assets, More. Each tab owns a `NavigationStack` whose path lives in
  `Router.paths[tab]`. Re-selecting the current tab pops to root.
- **Push**: `router.push(.projectDetail(id: p.id))` (current tab) or `router.push(.credits, on: .more)`.
- **Pop**: `router.pop()`, `router.popToRoot()`. **Switch tab**: `router.select(.studio)`.
- **Sheets**: `router.present(.newProject)` / `router.dismissSheet()`. Add cases to `AppSheet`, render in `SheetHost`.
  Router sheets present at the `.large` detent (`AppSheet.detents`) so form headers never get clipped; local
  `.msSheet(isPresented:)` pickers may still use `[.medium, .large]`.
- **More tab** lists every secondary screen, including a *Tools* section for the generators (Image, Video, UGC,
  Product Shoot, Ads, Copywriter, Hooks, Assistant) so each route is reachable without going through the Studio.
- **Templates → Studio**: `TemplateDetailView` sets `store.pendingTemplateId` and selects the Studio tab;
  `StudioView.consumePendingTemplate()` applies prompt/style/ratio (and picks Image vs Video mode from the format).
- **Toasts**: `router.toast("Saved", style: .success)`.
- Never build `NavigationLink`s by hand — always go through `AppRoute` so deep links stay consistent.

### Adding a screen

1. Add a case to `AppRoute` in `Router.swift` (use associated `id: String` for detail screens).
2. Create `Views/Screens/<Name>View.swift` (or replace the placeholder that already exists).
3. Add the case to the `switch` in `Views/Shell/RouteDestination.swift`.
4. Run `xcodegen generate` if you added a file, then build.

Placeholder screens already exist and are wired for every route; replace the body of the matching file.
Detail placeholders already take their id (`CampaignDetailView(campaignId:)`, `AssetDetailView(assetId:)`,
`TemplateDetailView(templateId:)`, `ContentCalendarView(campaignId:)`).

## Store surface (`AppStore`, `@EnvironmentObject`)

State: `user, onboardingDone, onboardingAnswers, projects, assets, campaigns, generations, favorites,
brand, credits, transactions, notifications, members, plan, preferences, currentProjectId, copyResults,
savedHooks` + static `templates`, `creators`.

Derived: `currentProject, activeProjects, unreadNotificationCount, recentAssets, recentGenerations,
project(_:), asset(_:), campaign(_:), template(_:), creator(_:), generation(_:),
assets(in:), generations(in:), campaigns(in:)`.

Actions:
- Onboarding: `completeOnboarding(_:)`
- Projects: `createProject(name:description:)`, `updateProject`, `renameProject`, `duplicateProject`, `archiveProject`, `unarchiveProject`, `deleteProject`, `setCurrentProject`
- Favorites: `isFavorite(kind,id)`, `favoriteIds(kind)`, `toggleFavorite(kind,id)` — kinds: `.asset .template .prompt .creator`
- Assets: `addAsset(name:kind:imageURL:projectId:tags:durationSeconds:)`, `updateAsset`, `renameAsset`, `moveAsset`, `deleteAsset`
- Generations: `addGeneration(kind:prompt:thumbnails:projectId:model:credits:status:resultText:)`, `updateGeneration`, `setGenerationStatus`, `deleteGeneration`, `addCopyResult`, `saveHook`
- Campaigns: `createCampaign(name:objective:audience:platforms:formats:projectId:assetIds:variations:)`, `updateCampaign`, `setCampaignStatus`, `deleteCampaign`, `addAssets(_:toCampaign:)`, `addCalendarItem(_:to:)`, `updateCalendarItem`, `removeCalendarItem`
- Brand: `updateBrand`, `updateBrandVoice`
- Credits: `spendCredits(_:reason:) -> Bool`, `canAfford`, `buyCredits(_:price:)`
- Notifications: `pushNotification(kind:title:message:)`, `markRead`, `markAllRead`, `deleteNotification`
- Workspace: `inviteMember(name:email:role:)`, `removeMember`, `changeRole(_:to:)`
- Plan/profile: `setPlan`, `updateUser`, `updatePreferences`, `resetAll()`, `saveNow()`

Persistence is automatic: every `@Published` change schedules a debounced (400 ms) JSON save to
UserDefaults under `marketingstudio.state.v1`. `resetAll()` wipes it and returns to onboarding.

## Mock API surface (`MockAPI`, `@MainActor enum`)

All calls `async throws`, sleep 0.6–2.5 s, charge credits (`MockAPIError.insufficientCredits` if short),
log a `Generation`, and often push a notification.

```swift
generateImage(ImageGenParams, store:) -> [GeneratedImage]          // 4 results, 40 credits
upscaleImage(url:store:) -> GeneratedImage                          // 15 credits
generateVideo(VideoGenParams, store:, progress:(String)->Void) -> GeneratedVideo   // emits MockAPI.videoSteps
generateUGC(UGCParams, store:, progress:) -> GeneratedVideo
generateProductShoot(ProductShootParams, store:) -> [GeneratedImage]
generateAds(AdParams, store:) -> [AdVariation]                      // Creative A–D
generateCopy(CopyParams, store:) -> CopyResult
generateHooks(product:audience:store:) -> [HookResult]              // 10 hooks
createCampaign(CampaignParams, store:, progress:) -> Campaign       // creates assets + variations + calendar
exportAssets(ids:format:quality:store:, progress:(Double,String)->Void) -> Asset
uploadProduct(name:store:, progress:(Double)->Void) -> Asset
assistantReply(to:store:) -> String
```

Typical usage in a view:

```swift
@State private var loading = false
@State private var results: [GeneratedImage] = []
...
loading = true
do { results = try await MockAPI.generateImage(params, store: store); router.toast("4 images ready", style: .success) }
catch { router.toast(error.localizedDescription, style: .error) }
loading = false
```

## Conventions

- Colors only via `MSColor`; accent (`MSColor.accent` / `accentGradient`) is reserved for the primary CTA and selection.
- Surfaces: `.msCard()` for lists/cards, `.msElevated()` for floating bars/sheets, `.msScreen()` on every screen root.
- Horizontal gutter is `MSSpacing.gutter` (20). Use `SectionHeader` for section titles.
- Screens use `.navigationBarTitleDisplayMode(.inline)`; tab roots put `.toolbar { MSTopBarItems() }` (credits + bell).
  Prefer an in-content `Text(...).msTitle()` over large navigation titles.
- Images: `RemoteImage(url:cornerRadius:)`; picsum seeds `https://picsum.photos/seed/<slug>/800/1000`, avatars `https://i.pravatar.cc/300?img=N`.
- Labels drawn on top of imagery use `MSBadge(tone: .overlay)` (white on translucent black); the tinted tones are for
  badges on card/list surfaces. On the Studio canvas pass `badge:` to `StudioZoomableImage` so the label sits on the
  fitted image rather than the canvas gutter.
- Every pushed screen sets `.navigationTitle(...)` (inline) even when it also draws an in-content `.msTitle()`, so the
  back bar is never blank. `SegmentedTabs` labels are Title Case, not uppercase.
- Rows of option chips that can overflow the width go in a horizontal `ScrollView` (see `GenerationBar`), never a
  plain `HStack` that truncates.
- Every list has an `EmptyStateView` with a CTA; every async action shows `SkeletonView`/`ProgressIndicator` while loading.
- Mutations go through `AppStore` actions only; views never write to arrays directly.
- Haptics via `MSHaptic.tap()/success()/warning()`; animations via `MSAnimation.snappy/gentle/slow`.
- No emojis in UI copy; no Foundation `Notification` name clash — the model is `AppNotification`.
